# Тиждень 1 — Discovery + Query Generator

Деталізація розділу "Тиждень 1" з `docs/ai_visibility_fintech_plan.md`.
2 робочі дні: День 1 — середовище + Discovery Agent, День 2 — Query Generator.

## Мета тижня

На виході — `queries.json` з класифікованими запитами (за intent) для
**пілотного набору з 2 брендів** (Stripe, Paddle — навмисно контрастна пара:
enterprise-фокус vs SaaS/no-code фокус, достатньо для comparison-запитів),
згенерований на основі людино-підтверджених профілів брендів.

Повний список з мастер-плану (Stripe, Adyen, Checkout.com, Paddle, Mollie)
лишається цільовим для наступних тижнів (3-8) — розширення з 2 до 5 брендів
робиться пізніше, коли pipeline вже перевірений на малому й дешевому наборі.
Технічно нічого не змінюється: досить додати 3 назви в конфіг і перезапустити
Discovery + Generator.

## День 1 — Середовище + Discovery Agent

### 1. Структура проєкту

    aivisibility/
      __init__.py
      common/
        __init__.py
        config.py          # завантаження .env, константи (список брендів — 2 для пілоту)
        schemas.py          # Pydantic-моделі: BrandProfile, Query
      discovery/
        __init__.py
        agent.py            # DiscoveryAgent
      query_generator/
        __init__.py
        generator.py         # QueryGenerator
    data/
      brands/                # data/brands/stripe.json тощо — підтверджені профілі
      queries/                # data/queries/queries.json — фінальний результат
    scripts/
      sanity_check.py         # мінімальний виклик SDK, перевірка що все працює
    tests/
    .env.example
    .gitignore

### 2. Залежності (`pyproject.toml`)

- `claude-agent-sdk` — офіційний Claude Agent SDK (Python-пакет обгортає
  Claude Code CLI; **потребує Node.js + `npm install -g @anthropic-ai/claude-code`**
  — перевірити це першим, до написання агента, щоб не впертись в блокер
  посеред дня).
- `pydantic` — валідація схем (BrandProfile, Query).
- `python-dotenv` — опційно, тільки якщо знадобиться `ANTHROPIC_API_KEY` як
  запасний варіант.
- (опційно) `rich` — зручний CLI-вивід для кроку human-in-the-loop.

### 3. Авторизація

Авторизація через уже залогінений **Claude Code Pro** (`claude login`) —
окремий `ANTHROPIC_API_KEY` не потрібен, якщо SDK підхоплює цю сесію. Це
перша річ, яку перевіряє sanity check нижче. Якщо не підхопить — тоді запасний
варіант: `.env` з `ANTHROPIC_API_KEY=` (`.env.example` як шаблон,
`.gitignore`: `.venv/`, `__pycache__/`, `.env`, `*.pyc`).

### 4. Sanity check (перше, що робимо в День 1)

`scripts/sanity_check.py` — мінімальний виклик Claude Agent SDK (простий
`query()` з тривіальним промптом), щоб підтвердити: Node/CLI встановлені,
сесія Claude Code Pro підхоплюється (без API-ключа), SDK повертає відповідь.
Не рухаємось далі, поки це не пройде.

### 5. Discovery Agent (`aivisibility/discovery/agent.py`)

- Вхід: назва бренду (+ опційно URL).
- Використовує Claude Agent SDK з увімкненим web search.
- Промпт: дослідити бренд і повернути JSON, що відповідає схемі
  `BrandProfile`:
  - `niche: str`
  - `competitors: list[str]`
  - `target_audience: str`
  - `key_use_cases: list[str]`
- Парсинг відповіді → валідація через Pydantic. Якщо не валідна — retry з
  уточненим промптом (1-2 спроби, далі — ручне втручання).
- **Human-in-the-loop**: чернетка профілю пишеться в
  `data/brands/<brand>.json`, у консоль виводиться короткий summary. Цикл
  підтвердження:
  - `y` — прийняти як є
  - `e` — відкрити файл на ручне редагування, після Enter — перевалідувати
  - `r` — перегенерувати заново
- Прогнати для 2 пілотних брендів: Stripe, Paddle.

### Критерії готовності Дня 1

- [x] `scripts/sanity_check.py` відпрацював без помилок (Claude Code Pro сесія
      підхоплена)
- [x] 2 файли `data/brands/*.json`, кожен валідний за `BrandProfile`
- [x] У кожному профілі — непорожня ніша, ≥2 конкуренти, цільова аудиторія
- [x] Профілі явно підтверджені користувачем (не сирі чернетки моделі)

## День 2 — Query Generator

### 1. Таксономія запитів і схема

Категорії intent (з мастер-плану + fintech-специфічні):
`awareness`, `comparison`, `transactional`, `use-case`, `fees_pricing`,
`geography_coverage`.

Pydantic-модель `Query`:
- `text: str`
- `intent: Literal[...]` (6 категорій вище)
- `brand: str`
- `mentions_competitors: list[str]` (які конкуренти явно згадані в запиті,
  якщо є — важливо для comparison-запитів)

### 2. Генератор (`aivisibility/query_generator/generator.py`)

- Вхід: підтверджений `BrandProfile` (з Дня 1).
- Для кожного бренду × кожної з 6 категорій — генерація N запитів одним
  викликом Claude (без web search, чиста генерація на основі профілю +
  кількох few-shot прикладів для стилю "реального користувача").
- Стартове N = 2 на категорію на бренд → 12 запитів/бренд → **24 всього**
  (для 2 пілотних брендів). Дешево й достатньо, щоб вручну перевірити всі
  запити, а не тільки вибірку. Легко збільшити пізніше (і N, і кількість
  брендів), якщо буде мало для week 3-4 статистики.
- Дедуплікація: точний збіг тексту (case-insensitive) в межах бренду —
  прибрати дублікати, регенерувати нестачу.
- Агрегація 2 пілотних брендів → `data/queries/queries.json`.

### 3. QC (легкий, без окремої інфраструктури)

- Ручний перегляд усіх 24 запитів (набір настільки малий, що вибірка не
  потрібна) на реалістичність.
- (Опційно, не блокер) — прикинути токени/вартість генерації по кожному
  бренду, як заділ під звичку логувати вартість з Тижня 2.

### Критерії готовності Дня 2

- [x] `queries.json` містить запити для 2 пілотних брендів (Stripe, Paddle)
- [x] Усі 6 категорій представлені для кожного бренду
- [x] Немає точних дублікатів тексту в межах бренду
- [x] Повний перегляд не виявив мусорних/нерелевантних запитів

## Фінальний результат тижня 1

- `data/brands/*.json` — 2 підтверджених профілі брендів (пілот)
- `data/queries/queries.json` — 24 запити, валідні за схемою
- Скелет пакету `aivisibility/` (common, discovery, query_generator) —
  розрахований на будь-яку кількість брендів, розширення до повних 5
  (Adyen, Checkout.com, Mollie) — це зміна конфігу, не коду
- Робоче середовище (SDK, авторизація через Claude Code Pro, .gitignore) —
  готове для Тижня 2 (Prober)

## Відкриті питання / ризики

- Claude Agent SDK тягне залежність на Node.js + CLI — на Windows/PowerShell
  перевірити окремо, це найімовірніша точка "муляки" в День 1.
- Якщо Claude Agent SDK не підхопить сесію Claude Code Pro автоматично —
  запасний варіант: `ANTHROPIC_API_KEY` (окрема оплата за токени).
- N=2 запитів/категорію і 2 бренди — навмисно маленький пілот для дешевого й
  швидкого end-to-end прогону; масштабування до повного набору — окрема
  наступна дія, не частина цього тижня.
- Web search у Discovery Agent може віддати застарілу/неточну інформацію —
  тому human-in-the-loop крок обов'язковий і не повинен пропускатись заради
  швидкості.
